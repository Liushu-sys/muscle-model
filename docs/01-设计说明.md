# 01 · 设计说明：这个模型是怎么搭起来的

> 面向"要改它 / 要接它"的人。只读使用说明的话看 README 就够了。

## 一句话结构

```
图（47 组矢量路径，左右可分开）  ←→  映射（9 条模式：症状 → 肌肉）  ←→  引擎（输入一句话，输出诊断）
                                                    ↓
                                              动作库（50 个，按场景挑 3 个）
```

三层各管一件事，**中间那层（模式）是整套设计的支点**。

---

## 1. 图：从 3D 模型到左右可分的 SVG

原始素材是一个解剖 3D 模型（`anatomy.glb`，25MB，太大不入 git）。

```
anatomy.glb
  → tools/extract_body_svg.py   投影出正/背两张 SVG，按肌肉分组
  → assets/body_paths.json       47 组 × 正/背，每组一条 path 的 d 属性（91KB）
  → tools/gen_body_sides.py      把每组拆成 left / right
  → assets/body_sides.json       左右分离版（103KB，组件直接读这个）
```

**左右怎么拆的**：矢量图左右对称，中线在 x=100（viewBox 200×460）。

- **40 组天然分离** —— 它们的子路径本来就完全落在中线一侧，直接按质心归边，零处理。
- **9 组跨中线**（枕下肌群、头夹肌、上斜方肌、菱形肌、中斜方肌、背阔肌、竖脊肌、臀大肌、下斜方肌，**全在背面**）——
  这些肌肉本来就是跨越脊柱的一整片。做法不是切断路径，而是**同一条路径渲染两遍、分别用 clipPath 裁到 x<100 和 x>100**，
  标 `needsClip: true`。一个方案覆盖全部 47 组，数据零改动，也保住了路径的完整形状。

`gen_body_sides.py` 会同时写 `assets/` 和 `src/assets/` 两份，免得改了图忘了同步。

### 陷阱：正面图上的左右是反的

- **正面图**：屏幕左边 = 身体的**右**侧（你在照镜子）
- **背面图**：屏幕左边 = 身体的**左**侧（你在看别人的背）

`screenToBody(view, side)` 就是这个换算，而且它是**自反的**（`bodyToScreen` 是同一个函数）。
`MusclePaint.sides` 里存的永远是**身体侧**，组件内部自己转。别在业务代码里手动翻。

## 2. 映射：为什么是"模式"而不是"肌肉"

书里写的不是"这块肌肉紧"，而是**「某个关节受限时，常见的一组肌肉表现」**。
比如《基础肌动学》p.89 肩胛胸壁关节那一段，列的是：胸大肌/胸小肌紧张，菱形肌/中斜方肌/前锯肌肌力减弱。

所以最小单位不是肌肉，是**模式（Pattern）**。目前 9 条：颅颈区、肩胛胸壁、肩（盂肱）、胸椎、肘、腕、髋、膝、踝。

**这个选择带来一个必须处理的后果**：
同一块肌肉在不同模式下角色可能相反——腘绳肌在膝模式是"紧张"，在髋模式是"肌力减弱"。

所以 `muscles.ts` 里的 `type` 字段只是**默认倾向**，真正判定永远要先认模式再看模式里它属于哪一侧。
这也是下面第 3 节"用户确认为什么只能否决不能指定"的根本原因。

## 3. 引擎：用户确认那一步为什么是"否决制"

流程是：一句话 → 引擎猜 → 用户在图上增删 → 重算。

用户那一动只有两种语义：

| 用户动作 | 语义 | 实现 |
|---|---|---|
| 点掉一块 | **否决**："这块不算" | 该肌肉进 `veto` 集合，从所有候选里剔除；所属模式降权（×0.55 连乘） |
| 补点一块 | **加分**："这里也有" | 所属模式加分（+0.22），并去重 |

**判定权始终在模式层**。用户不能在模式没给出的候选里凭空造一块新诊断——
补点的肌肉如果本次模式没判它，只会进 `marks`（第 3 页画成灰色中性态），
等于"尊重你点了，但不擅自给你判过劳/过弱"。

为什么这么设计：如果让用户"点什么就判什么"，第 2 节那个"同一块肌肉角色相反"的事实就被破坏了，
用户点一下腘绳肌，我们到底是判它紧还是判它弱？答案只能由模式给。

### 一个反直觉但正确的行为

点掉一块肌肉，有时会让**别的肌肉冒出来**。
因为否决会让原模式降分，原本排第二的模式可能升进候选。
实测：主诉"看手机脖子酸，头往前探，肩膀沉"，点掉「胸锁乳突肌」后，
命中模式从 `cranio_cervical` 变成 `cranio_cervical + scapulothoracic`，于是胸大肌、菱形肌进来了。

这不是 bug——**否决的是那块肌肉，不是那个部位**。用户觉得脖子有问题，
那"脖子这一片还有别的可能"本来就该重新排序。

## 4. 依据：分三级，说错了比不说更糟

书里按「模式」列名肌肉，所以**同一个肌肉 id 在不同模式下依据等级不同**。

| 等级 | 含义 | 在哪 |
|---|---|---|
| 书原句 | 书里白纸黑字列了这个模式里这块肌肉属于紧张侧/减弱侧 | `pattern.tight` / `pattern.weak` |
| 同群推断 | 书里列名了它所在的肌群，这条是同群推的 | `pattern.inferredTight` / `inferredWeak` |
| 常识判断 | 书里没提，按解剖与常见体态判断 | 同上，且无 bookPage |

解释卡里的"依据《基础肌动学》第4版 p.xx"**只准挂在书原句上**。
推断项必须写成"参考 p.xx（该处未点名这块肌肉，属同群推断）"。

> 打包时修过一个真 bug：早期版本用 `muscles.ts` 的 `bookNote` 判断依据等级，
> 结果把书 p.89 原句列名的**菱形肌**说成"该处未点名，属同群推断"——
> 等于把书里的依据说没了。根因就是书是按模式列名的，不能按肌肉全局标。

图上区分：主项是实线填充，推断项是**虚线**。用户扫一眼就知道哪条是硬依据。

## 5. 动作库：为什么是"标签挑选"而不是矩阵

47 肌肉 × 4 场景 × 3 个动作 = 564 条文案，写不动也维护不动。

改成：**50 个动作，每个带标签**（目标肌肉 / 部位 / 适用场景 / 器械 / 姿态 / 方向），
用 `pickActions()` 现挑。挑选分三层：

1. 命中本次诊断肌肉 **且** 方向不重复（避免三个都是拉伸）
2. 命中肌肉，允许方向重复
3. 才轮到"部位兜底"

**第 2 层优先于第 3 层**是刻意加的：早期版本把命中肌肉和部位兜底混在一起排，
结果一条低分兜底动作（只是因为方向不重复）会把高分命中动作挤掉。

还有一条诚实性约束：**"针对："后面只准出现本次诊断出的肌肉**。
没命中就降级成"相关部位：颈肩一片"（`actionTargetLabel().exact === false`）。
当前 36 个真实组合里还有 9 处走兜底——不算错，但越少越好。

第 4 页另外有个硬规则：**过劳组给 2 个、过弱组给 1 个**，不是 3 个全给过劳。
光拉伸不补弱，过两天还会回来。

## 6. 已知边界

- **47 组里只有 33 组能被本地 9 条模式点亮**，剩下 14 组是备位（梨状肌、多裂肌、斜角肌…）。
  要覆盖它们得补模式或接 AI 引擎（`engine.buildSystemPrompt()` 已经留好了）。
- **体感词匹配是字面匹配**，不是语义理解。曾经出过"手肘外侧疼"被判成膝盖
  （和「跑步膝盖外侧疼」共用「外侧」「侧疼」，单字覆盖率只有 0.43 就命中了）。
  现在加了覆盖率下限 0.5，并且 `tools/smoke_local.mjs` 里有一条**体感词自洽检查**：
  每条 senses 喂回去必须指向它自己所属的模式。
- **肌肉图是 2D 投影**，不表达深浅。渲染时按"先画未着色的、再画着色的"两遍画，
  否则深层小肌肉（冈上肌、多裂肌）会被表层大肌肉盖住，永远点不到。
