## 八、后续分析规则方案（阶段 5 交付；只出方案，不改代码）

### 8.1 基本流程（第一版：取消主观感受输入）

```
用户点击区域（regionId + side）
  → [分析层] 左右侧合并（6.1 规则）
  → 查 REGION_CANDIDATES[regionId] 获得候选肌肉（local/referred/stabilizer）
  → 查 MUSCLE_PATTERN_INDEX：候选肌肉 ∈ 哪些模式（书模式 P-xx 为主）
  → 命中模式（一个区域可命中多个）：
      上半身 → 附加 UCS-01 框架解释；下半身 → 附加 LCS-01 框架解释（E4 桥接规则）
  → 输出结构：
      ① 该区域包含哪些肌肉（科普）
      ② 关联模式（书中原名 + UCS/LCS 框架名，双层命名）
      ③ 模式中常见的紧张组 / 肌力减弱组（E1 优先，E2/E3 标「项目推断」）
      ④ 模式的常见整体表现与成因（书原文注释优先引用）
      ⑤ 动作：pickActions() 从已审核动作库按 sit/stand 筛选
  → 红旗词筛查（freeText 输入仍保留 18 词表，命中即阻断并提示就医）
```

### 8.3 AI 职责边界（与任务书第八节一致）

- **规则和知识库负责**：限定可用肌肉、模式、动作；决定哪些内容出现。
- **AI 只负责**：把上表固定内容组织成通顺大白话；生成四段解释卡（what/func/why/advice，docs/04 已有模板）；输出必须 JSON mode 且 id 只能在白名单内（`filterByLibrary` 前端校验保留）。
- **AI 不得**：创造肌肉 id、发明模式、编造动作、给出诊断结论。无 AI 时（离线/降级）规则引擎独立完成 ①-⑤ 全流程——现有 `matchPatternsBySense` 等本地函数即降级方案。

### 8.4 展示层规则（从知识表直接派生）

1. 同一肌肉多角色（菱形肌/腘绳肌/竖脊肌/上斜方肌）：文案永远带「在【某模式】中」前缀，禁止全局倾向表述。
2. E2/E3（推断项）在界面上用「参考/推断」弱化标记，不与 E1 同权重呈现（沿用现有虚线/实线设计）。
3. 下肢/上肢区域文案明确「该区域用关节受限模式解释，不属于上下交叉综合征范围」。
4. 模式命名双层：正标题用书中原名（如「颅颈区：头部过度前伸姿势」），副标题给框架名（如「上交叉综合征的相关成分」）。
5. 免责声明固定出现在分析结果底部：「以上为理论模式中的常见肌肉关系，不代表您个人肌肉状态的确认。」
